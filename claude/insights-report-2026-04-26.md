## 概览

### 做得好的地方
你建立了一套严格的闭环工作流：深度代码审查发现关键问题（MDC 泄漏、测试污染、空值遗漏），然后跨多个文件系统修复，并用全面测试覆盖验证每个变更。你展现了敏锐的边界情况思维——捕捉到如转义子句被应用到整个 WHERE 子句而非单个 LIKE 表达式这样的细微 bug，并坚持到全部 115 个测试通过才收手。

### 拖后腿的地方
Claude 的编辑经常引入回归——意外删除字段、破坏 WHERE 子句逻辑、使用无效的配置 schema——需要 2-3 轮修复才能正确。另一方面，会话经常在完成前被中断，并且没有提前明确技术约束或语言偏好，导致 Claude 走上需要中途纠正的错误路径。

### 快速见效的建议
要求 Claude 在每次独立变更后运行完整测试套件，而不是将多次编辑批量在一起。这能立即捕获回归（误删字段、损坏的 import），而不是在级联变更堆积后才被发现，将多轮修复压缩为单次迭代。

### 进阶方向
自愈 TDD 循环：Claude 生成实现、运行完整套件、检查每个失败、修复根因、重新运行——自主循环，仅在测试全绿或需要真正设计决策时才上报。配合并行 pre-commit 质量子代理，交叉引用 CLAUDE.md 约定、审计回归、阻塞合并直到所有关卡通过。

## 交互风格

你与 Claude Code 的交互方式像一位**技术精湛、亲临一线的指挥者**——委派实现但保持紧密的创意控制。你通常给出清晰的初始方向，然后通过**频繁的中断和重定向来迭代式完善输出**。至少有 8 次会话中，你中途打断 Claude 以纠正方向——无论是通过三次迭代重定向 `WebUtil.isAjax` 逻辑、在英文工作完成后要求中文提交消息，还是将 schema 字段用法从 `type/template` 纠正为 `command`。

你展现了**深厚的 Java/Spring 专业知识，并期望严格的工程标准**。你的主要领域是复杂的 Java 后端（1643 次与 Java 相关的工具调用），你经常链式执行多步骤工作流：代码审查 → 识别关键问题 → 跨多文件修复 → 添加全面测试 → 验证全部通过。例如，一次会话中在 9 个文件中发现了 3 个严重和 4 个重要问题，产生了 37 个全部通过的新单元测试。

当出现摩擦时（14 次 buggy 代码、9 次用户拒绝操作），几乎总是技术性的——错误的 API 使用、测试失败或错误的架构方法——而非误解你的意图。你很好地容忍了这些中途修正，只要最终交付物符合你的标准。

> **核心模式：** 像资深开发者审查初级开发者的工作一样与 Claude 结对编程——委派实现、密切观察执行、频繁中断以在完成前重定向方法或提高标准。

## 摩擦点

### 1. 需求被误解与错误方法
你经常需要暂停或中断 Claude，因为它采取了不正确的技术方法。
- Claude 剥离了所有 +86 前缀而未能按你意图有条件地保留，并创建了一个独立的类而非修改现有转换器
- Claude 连续两次使用了无效的 settings schema（`type/template` 而非 `command`），迫使你在重复验证错误后中断

### 2. Buggy 代码与重复修复循环
Claude 的编辑经常引入回归——意外删除字段、破坏 WHERE 子句逻辑或导致测试失败——需要多轮修复。
- 清理注释时，Claude 意外删除了 `originalUri` 字段，自动格式化工具又恢复了已删除的注释
- Claude 将 SQL ESCAPE 子句追加到整个 WHERE 子句末尾而不是每个 LIKE 表达式之后

### 3. 语言与约定不匹配
Claude 在你期望中文时默认使用英文，并在被纠正前假设了错误的文件路径或命名约定。
- Claude 用英文回复直到你提醒它使用中文（"记住用中文交互"）
- 16 个提交需要从英文重做为中文

## 要尝试的功能

### Hooks — 编辑后自动验证
在 `.claude/settings.json` 中添加：
```json
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Edit",
        "command": "cd ${CLAUDE_PROJECT_DIR} && ./mvnw test -pl gstack-core -Dtest='*' 2>&1 | tail -30"
      }
    ]
  }
}
```

### 自定义 Skills — 标准化工作流
创建 `.claude/skills/review/SKILL.md`：
```markdown
---
name: review
description: 中文代码审查，输出分级问题清单
---
对当前变更进行代码审查，以中文输出，按以下级别分类：
- 🔴 严重：安全漏洞、数据丢失风险
- 🟡 重要：性能问题、边界值缺失、异常处理不当
- 🟢 建议：代码风格、可读性优化
```

### Headless 模式 — CI 集成
```bash
claude -p "审查所有 Java 文件的空指针问题" --allowedTools "Read,Grep,Edit,Bash" --output-format json > review-result.json
```
