# 《第一次进入代码迷宫：Claude Code 入门冒险》漫画设计

## 背景

用户希望创建一部中文知识漫画，主题是“学习 Claude Code”。目标读者是完全没用过 Claude Code 的新手。漫画不做安装教程或完整命令手册，而是帮助读者建立正确的入门心智模型。

## 目标读者

- 完全新手：不知道 Claude Code 是什么，也不清楚它和普通聊天式 AI 的区别。
- 可能有少量编程兴趣或基础，但不能假设熟悉终端、Git 或测试流程。
- 需要通过故事理解“如何与 Claude Code 协作”，而不是背命令列表。

## 成品范围

- 类型：中文知识漫画。
- 长度：7 页，包含封面 + 6 页正文。
- 画风：`concept-story` 方向，即 manga + warm + standard。
- 叙事方向：选择“冒险导师型”，并吸收“工具箱教程型”的模块清晰度。
- 表现方式：关键命令使用大字卡片，复杂界面使用概念化画面表达。

## 核心叙事

主角“小岚”第一次面对陌生代码项目，项目被视觉化为一座“代码迷宫”。她害怕文件太多、命令太多、误改项目。Claude Code 以“悬浮终端窗口”的形式出现，像向导一样陪她探索迷宫。

Claude Code 不被描绘成自动完成一切的魔法，而是结对编程伙伴：它可以读项目、提出计划、修改文件、运行命令，但关键动作需要用户理解和确认。故事最终让小岚学会一套可重复的协作流程：明确目标 → 理解上下文 → 计划 → 小步执行 → 验证。

## 角色设定

### 小岚

- 身份：初次使用 Claude Code 的新手程序员。
- 视觉：背着小包，拿着笔记本，服装现代、亲切。
- 状态变化：开头姿态紧张、肩膀收缩；结尾姿态舒展，能主动提出下一步。

### Claude Code 向导

- 形象：悬浮终端窗口。
- 视觉：深蓝或黑色终端面板，边缘柔和发光，带简单表情符号和提示气泡。
- 性格：温和、克制、可靠。
- 行为边界：不抢走键盘，不宣称“我全自动搞定”，而是提醒用户确认目标、查看计划和验证结果。

### 代码迷宫

- 形象：项目文件夹、README、src、tests、Git 状态被视觉化为迷宫、书架和房间。
- 作用：让抽象项目上下文变成新手能理解的空间。

## 视觉符号系统

| 概念 | 视觉符号 | 用法 |
|---|---|---|
| 项目上下文 | 发光地图卷轴 | 标出 README、src、tests 等区域 |
| 明确任务 | 指南针 | 从乱转变为指向目标 |
| 计划 | 分步骤石板/任务清单阶梯 | 每一步亮起一个格子 |
| 命令执行 | 终端命令卡片 | 展示 `claude`、`/help`、`git status`、`npm test` |
| 验证 | 绿色印章、测试徽章、diff 放大镜 | 表示测试和变更检查 |
| 安全边界 | 红色护栏与确认门 | 表示危险操作需要用户确认 |

## 页面结构

### 第 0 页：封面

标题：《第一次进入代码迷宫：Claude Code 入门冒险》

画面：小岚站在巨大的代码迷宫入口，入口由文件夹和终端符号组成。悬浮终端窗口 Claude Code 在她身旁点亮道路。

学习目标：建立“这是一场协作式探索”的预期。

### 第 1 页：不是魔法，是协作

内容：小岚以为 Claude Code 会像魔法一样自动完成项目。Claude Code 解释自己是终端里的 AI 编程助手，可以协助读文件、改代码、运行命令，但需要明确目标和确认关键操作。

学习点：Claude Code 是结对编程伙伴，不是无人驾驶。

### 第 2 页：把愿望变成任务

内容：小岚说“帮我看看这个项目”。指南针乱转。Claude Code 引导她改成“帮我找到入口文档，并说明如何运行测试”。指南针指向目标。

学习点：清晰任务比模糊愿望更有效。

### 第 3 页：先读地图

内容：代码迷宫展开成发光地图。README、src、tests 三个区域亮起。Claude Code 说明要先理解项目结构和上下文，再决定怎么改。

学习点：修改前先让 Claude Code 了解项目。

### 第 4 页：先计划，再行动

内容：前方出现多条岔路。Claude Code 展示任务清单阶梯：读文件、定位入口、提出修改、运行测试。小岚先确认计划，再迈步。

学习点：复杂任务要先计划，小步推进。

### 第 5 页：命令不是黑箱

内容：终端命令卡片飞出：`git status`、`npm test`。输出不用逐字显示，而用红绿状态条和测试徽章表现。小岚看到命令结果后理解当前状态。

学习点：Claude Code 可以运行命令，但结果要可见、可解释。

### 第 6 页：验证与边界

内容：小岚用 diff 放大镜检查变化，给通过的测试盖上绿色印章。迷宫出口前有红色确认门，提示危险操作需要用户确认。结尾小岚拿着地图和 Claude Code 继续前进。

学习点：完成前要验证；安全边界不是阻碍，而是保护。

## 文字策略

为了降低生成图中文字乱码风险，采用“少量大字 + 画面隐喻”的文字策略。

- 每页保留 1 个醒目的中文标题短句。
- 每格对话控制在 8–14 个汉字左右。
- 关键命令使用大号卡片展示。
- 复杂终端输出不逐字渲染，只用状态条、徽章、放大镜表现。

示例短句：

- “先告诉我目标。”
- “我们先读地图。”
- “计划确认，再行动。”
- “跑完测试再说完成。”
- “危险操作要确认。”

## 不包含内容

- 账号登录、订阅和安装细节。
- 全量 slash command 列表。
- MCP、Hook、Skill 等高级配置。
- 企业级权限策略深水区。
- 具体语言或框架的完整调试教程。

## 成功标准

读者读完后应该能说出：

1. Claude Code 是在终端里协助编程的 AI 助手。
2. 它可以读文件、改文件、运行命令，但关键操作需要人确认。
3. 好的使用流程是：明确目标 → 理解上下文 → 计划 → 小步执行 → 验证。
4. 不要把 Claude Code 当自动驾驶魔法，要把它当结对编程伙伴。

## 后续生成要求

- 输出目录建议使用 `comic/claude-code-adventure/`。
- 先生成 `analysis.md`、`storyboard.md`、`characters/characters.md`。
- 每张图的最终 prompt 必须先保存到 `prompts/`。
- 多页漫画建议先生成角色参考图，确保小岚和悬浮终端窗口在各页中保持一致。
- 若图片生成后出现文字错误，不通过程序覆盖修补，应修改 prompt 后重新生成。
